# 前端測試與真實操作驗證(R19)

> 一句話:**在瀏覽器實際用過才算完成** —— 不是「code 寫完、型別過了」。
> 從一個真實專案抽取:該專案的探針單日錯十次、e2e 假紅 45 條隔離後剩 4 條,
> 這一份把那些代價寫成規則。

## §1 驗證迴圈(P0,每次前端改動)

1. 啟 dev server
2. 用 **Playwright(MCP 或腳本)驅動真實瀏覽器**走使用者流程 ——
   讀 **a11y tree / DOM 斷言**為主(比像素穩),截圖為輔
3. 觀察 → 改 code → 再走一遍
4. **在瀏覽器實際用過才算完成**。「渲染出來了」不是「操作得動」:
   schema 收得下 → 渲染面畫得出 → **使用者操作得動**是三層,前兩層綠不代表第三層
   (實證:設計器連點四次建了四個元素全疊在同一格,疊住之後連點選都做不到)

## §2 走通即固化(P0)

- 手動/AI 走通的流程**存成 Playwright spec 進 CI** 當回歸
- AI 驅動瀏覽器慢且非確定性 ⇒ **只做探索與產測試,不放 CI**
- 🔴 spec 寫完要**真的跑過一次綠的**再 commit —— 「從來沒通過過的 spec」
  是〈檢查存在但不在會跑的那組〉第四種形狀,擋不住任何回歸

## §3 分層(金字塔底最大)

| 層 | 工具 | 覆蓋 |
|---|---|---|
| 快層(佔多數) | 單元 + Testing Library | 元件互動:欄位/驗證/格線 |
| 關鍵流程 | Playwright e2e + **testcontainers 真 DB** | 登入/租戶隔離/建單→關鍵業務流 |
| AI 探索 | Playwright 驅動真瀏覽器 | 開發期驗證 + 邊角組合(不進 CI) |
| 視覺回歸 | screenshot | 版面 regression |
| 可重現底盤 | 確定性 seed / factory / MSW / 凍結時鐘 | 讓上面全部可重跑 |

## §4 spec 的品質規則(每條都付過代價)

- **反向斷言不可省**:「擋下來要出訊息」要配「合法的要放行」——
  少了後者,「一律擋」也讓前者全綠。「少了什麼」型驗收要配一條「還會動嗎」
- **驗數字不只驗字樣**:斷言「縮到」兩個字放過了「縮到第 0 列」(做不到的指示)
- 選擇器:**子字串定位器會誤中**(`hasText:"日期"` 撞到「出生日期」);
  input 的 value 是 property,`hasText` 讀不到;用 `data-*` / role / exact
- 等待:**等待訊號常在目標出現之前就為真**(骨架是靜止的,「不再變」被高原滿足);
  `.count()` 是當下快照不會等 —— 「修好了」而報告與修之前一模一樣
- 造資料的形狀就是測試的範圍:helper 的「額外正確」會把某狀態排除到不可能出現;
  乾淨 fixture 藏住只有舊資料會踩的缺陷

## §5 假紅的判讀(全套紅先隔離)

- **一整批紅先隔離重現**:45 紅隔離後剩 4 真紅;`timedOut` 與 `failed` 分開數
  (前者高負載下常是假紅),先看 `uptime` —— 而 load 可能是你自己起的 server
- 🔴 **e2e 會沿用別人的 dev server**(`reuseExistingServer`)⇒
  「只在 e2e 生效」的環境變數永遠 false;判別法一行 `lsof` 看它用哪個 dist dir
- 背景 e2e 跑到一半別改它正在測的檔(熱重載讓失敗長得像產品缺陷,整批作廢)
- 事先寫的紅燈歸因幾乎一定錯:分「產品壞 / 測試過期 / 環境漂移」逐條驗,
  **「測試過期」的另一半常是產品真的壞了**(裁定落地了而測試留在原地 ⇒
  順著改測試前先問「這個行為現在對嗎」)

## §6 量測(截圖與探針)

- 🔴 **設定看原始碼,溢出看截圖**:截圖看不出 variant(disabled 把 primary
  畫成次要);而版面撐爆只有截圖看得到 —— 兩邊都要,用對邊
- **「版面/骨架不一樣」的第一個動作是量面與盒子,不是找缺件**:
  底色/盒子層/容器寬/內距三份並排(現況 × 權威稿 × 參照頁)——
  「東西都在但長得不對」比「少了東西」常見得多,而存在性檢查看不到它
- 探針自檢:陽性 + 陰性對照組(見 memory 量測 pitfall);
  bbox 在動畫/佈局位移中會過期(靠近 → 等落定 → 重量 → 進入)
