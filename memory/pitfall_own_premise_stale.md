---
name: 「我方沒有 X」寫下來的當天可能就是錯的
description: 一輪七次前提全錯;task/doc 裡的斷言要附查法
type: pitfall
---

一輪之內七次「前提是錯的」:「X 整個沒有」早就出貨、「該加 Y」兩天前裁定不做、
「前置未解除」11 天前解除 —— 七次全靠動手前順手對碼抓到,而那是習慣不是機制。

**規則**:task / doc / 註解裡寫「我方沒有 X」「只有 Y」時,**同一句附查法**
(哪個 grep、哪個檔、哪一行、日期)⇒ 下一次直接重跑那個查法,不必從頭想當初怎麼確定的。
變形:憑記憶寫 task、從「兩邊不同」推「還沒裁」—— 裁定住在檔頭與 OQ 表,先查再寫。
