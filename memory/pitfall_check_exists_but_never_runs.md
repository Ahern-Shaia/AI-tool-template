name: 檢查存在,但不在會跑的那一組裡
description: 四種失效形狀;要補的是「跑檢查的清單」,而清單要被當清單跑
type: pitfall
---

比「沒有檢查」更難發現的是「檢查存在但沒有人跑」。四種形狀:

1. 出貨前清單沒列它(大家跑的是子集)
2. 沒人跑那份清單(憑印象挑幾支)
3. 名字指向的東西不存在(文件裡的指令是幻覺,沒有人整份跑過)
4. 🔴 **它從來沒有通過過**(spec 寫完沒跑就 commit;test-results 裡上一次的 status 是 unexpected)

CI 也算:job **0 個 step、沒有 log、3 秒** = 沒開始跑,不是測試失敗 ——
「CI 會抓到」在每日排程下的實際意思是「明天會抓到」。

**判別法**:報全綠前確認跑的範圍 = CI 的範圍;看報告**筆數**(21 筆的全綠與 2245 筆的長一樣);
`Running N tests` 要對得上結尾 `N passed`。
